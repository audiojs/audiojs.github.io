# audio.js.org

The audiojs website: home, modules (`modules/`), utilities (`util/`), lab articles (`lab/`), archive. Static files, no build step on the server.

## Deploy

- A push to `main` publishes https://audio.js.org within a minute (GitHub Pages, "Deploy from branch: main"). No workflow, no other repo involved.
- audiojs.dev and audiojs.org redirect to audio.js.org at Cloudflare, path kept.

## Develop

- `npm run dev` serves the site as audio.js.org does: this repo at `/`, a checkout of audiojs/audio beside it (`../audio`, or `AUDIO=path`) at `/audio/`, else the live site's `/audio/` (`scripts/serve.mjs`).

## Before pushing

- Utility pages, the lab's frame and the site's chrome in every page are generated: after editing `scripts/util-pages.mjs`, `scripts/util-icons.mjs`, `scripts/util-previews.mjs`, `scripts/pages/*`, `scripts/lab-pages.mjs`, `scripts/bar.mjs`, `bar.css`, `bar.js` or an article's headings, run `npm run build`.
- Run `npm run test:all` (utilities in Chromium, Firefox, WebKit; pages; lab; home). Needs the network: packages load from esm.sh.
- The home and the lab embed the playground from `/audio/playground/`: a change that needs a newer playground goes live only once audiojs/audio has deployed it.

## Not in this repo

- The playground is audiojs/audio's own Pages, served at `/audio/` (deployed by that repo's CI). Link to it as `/audio/playground/`, embed it with `/audio/playground/embed.js`.
- The design system's tokens (`/audio/assets/tokens.css`), Geist (`/audio/assets/geist.woff2`) and the logo's mark (`/audio/logo/mark.js`) come from there too.
- `lab/logo/` is the logo's lab, any signal through any window: it draws with `/audio/logo/logo.js` and moves with `motion.js`. `lab/logo/logo.test.mjs` tests them in a browser, from the checkout beside this one.
- GitHub serves the org's other Pages repos under this domain: `/audio/`, `/web-audio-api/`, `/docs/`, `/test/`, `/stretch/`, `/beat/`, `/shift/`, `/web-audio-write/`. Never create folders with those names here.

## Keep

- `playground.html`, `editor.html`, `embed.js` at the root: forward the playground's old addresses (shared `#code=` links, embeds on other sites) to `/audio/playground/`.
- `sw.js` at the root: removes the playground's old service worker from browsers that registered it here.
- `funding.json`, `.well-known/`: the funding manifest.
- `CNAME`: `audio.js.org`, exactly as GitHub wrote it.
- `archive/2026/`: frozen snapshots of the old audiojs.dev home and the old audio.js.org page. Don't edit.
- The footer's credit for `home/blackbird.mp3` (Diana Tudor, xeno-canto 1059970, CC BY 4.0, an excerpt), while the home plays it.

## Every page

- One header, the same head lines (Geist, the tokens, `bar.css`, `bar.js`): `scripts/bar.mjs` writes both into the home, the lab and the modules page, and gives them to the utilities' and the modules page's generators. Don't edit them in a page.
- `bar.js`: the header's mark, drawn live by `/audio/logo/mark.js`, moving with any embedded playground's `mark` events; the links' ticks under a `.ticked` label, 1 px tall in a page, 4 px in the header's menu (the one under the pointer swells to fill its 4 px, the others thin with distance).
- Colours, sizes and motion are the design system's tokens. Black and white; one family, Geist: Sans, and Geist Mono for code, the dossiers and the home, set as a spec (`fonts/geist-mono.woff2`, OFL, this site's own: `bar.css` sets `--font-mono` to it over the tokens' system mono). JS after the word in outline, as tall as its x. A page lies on the dot grid (`--dots`), its column filled (`--sheet`).
- A page under the header is a `.site-page` (bar.css), as wide as the home: a `.site-rail` beside its `.site-main` on wide screens, sticky, the part in sight marked by `bar.js`; a scrolled row over it on narrow ones.

## Utilities

- `util/` is generated by `scripts/util-pages.mjs`: each utility's page, its rail every utility by shelf (`SHELVES`: convert, measure, clean up, edit, separate, voice, make); the index, the utilities on those shelves. Each has an icon, drawn in `scripts/util-icons.mjs` (32 px, line only); a new utility needs one there and a place on a shelf, else it lands under More with a plain wave. The home features a few (`FEATURED`), each with a preview drawn in `scripts/util-previews.mjs` (200 × 72 px, line and dot); a featured utility needs one.

## Lab

- `scripts/lab-pages.mjs` (in `npm run build`) frames the articles: each `h2` an id, the rail its contents; the front page a magazine, the first article across the page. Write articles as before, in a plain `<main>`; the script wraps them. `lab/logo/` is a stage and stays out of it.

## Home

- `index.html` + `home/`: the playground embedded (`<audio-repl>`) on the blackbird. Its attributes name what it shows (`controls`), its quick edits (`ops`) and its ground (`background="page"`: the page's own colour, read off the page). Under it, on paper: the doors (modules, utils, CLI, lab, playground, agents), the utilities featured (written by `scripts/util-pages.mjs`, with how many there are in all), the desktop app (coming), the lab's articles. `home/index.js`: the install button. Test: `npm run test:home`.

## Modules

- `modules/` is generated by `npm run modules` (`scripts/modules-page.mjs`) from the checkouts, not npm: audio (`../audio`), the @audio family repos (`~/projects/@audio`, or `AUDIO_ROOT`) and the libraries under them (`~/projects/<repo>`, or `PROJECTS`). The catalog lists units, audio first, then by name: a family's own package with the others folded under it (a search opens the folds it finds in), or a category over its libraries (`CATEGORIES`: platform, dsp, util, ui; a new library needs a place in one). Each family and each library carries tags (`TAGS`: what it is for, as many as fit); the rail filters by them. A new family or library with no tag is named when the script runs: give it its tags. Each package gets a dossier, `modules/<name>/`, set as a technical file (`.work/website.md`, CIA Aesthetics): its standing (calibrated for version 1 or later, pending calibration for version 0, deprecated), npm version and licence, its last change (git), the standards its README names (also down the sheet's edge), then its README (maths as MathML by KaTeX, relative links to sibling dossiers, its parts numbered). Pictures come from the commit last pushed, through jsDelivr; the package's own SVG plots sit on the dark with their inks inverted, each figure numbered. Run it after a package's README or version changes.
- `modules/index.js` (tags and search, both in the address; on a dossier's page, its place in the rail in sight; a dossier is a page of its own, a breadcrumb up, previous and next at its top and foot) and `modules/modules.css` are written by hand.
- The utilities link the packages they run on to their dossiers (`pkg()` in `scripts/page-helpers.mjs`), npm only where there is none.
